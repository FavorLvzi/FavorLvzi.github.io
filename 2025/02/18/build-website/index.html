Ubuntu 22.04搭建Hexo Next主题博客过程详解

发表于 2025-02-18 更新于 2025-04-24 分类于 文章 ， 技术 ， 网站搭建

前言

时常调侃自己的工作是给技术打杂的，就好比砖匠的小徒弟每天天给师傅和泥、递水。当然，也感谢上级能给我如此多的空余时间好让自己提升技术水平。前段时间偶然间在网上看见搭建个人博客的教程，加之本人也有考虑过作这方面的尝试。于是便开始左手准备了。虽然在搭建过程中遇到了不少问题，但幸好有AI可以答疑。
最开始时暂选的主题是Particlex（Particle），但诸多效果不尽人意，最后也就选择了功能更为强大的Next主题（参考iissnan/hexo-theme-next: Elegant theme for Hexo.）。
部署方面，最开始使用Github自带的Github page进行静态页面的部署，但考虑到访问效率的问题，最终选择了Netlify(虽然是国外的平台，但庆幸国内也能访问，并且速度还不错)。之所以选择Netlify,一是访问国内速度尚可，二是个人版免费，三是部署简便。
本文所讲的90%内容都可以在README.md以及Next主题官文theme-next.js.org中找到。我所作之事不过是拿来用罢了，就好比木匠师傅把椅子的腿腿打磨好了，徒弟只需将其斗好便可。

初始化Hexo博客项目

本文以 /var/www/hexo-next 为例,后续教程默认在此目录进行(统称项目根目录)

观察一下项目根目录：

  • _config.yml：Hexo项目全局YML配置文件，诸如git、主题等皆会在此配置
  • _config.landscape.yml：默认的Landscape主题配置文件，更换Next主题后可删除
  • node_modules：放着Hexo基础项目所需的包，安装npm也是为了管理这些包
  • *.json：两个json文件里记录了本项目所有包的版本，如果将该项目迁移到Docker或者其他系统中，均需要使用json文件进行构建
  • scaffolds：放着各种模板文件，Hexo项目最终是使用静态资源进行部署，将代码提交到GIthub时，也是提交的静态资源文件，而scaffolds则规定了Hexo需要生成静态资源的模板
  • source：放着各种本地资源文件，比如md文章文件。理应来说，图片等本地资源也需要放在此处，但在Next等流行主题项目结构里，图片等都是放在themes主题文件夹下的source里
  • themes：存放着主题所需的所有文件，如果你下载了两个主题比如ParticleX、Next，则此处也会有两个以主题名字命名的父目录，每个父目录下存放着该主题所需的所有文件

注：在执行完hexo三连后根目录下会多出一个public文件夹，此文件夹用于存放生成好的静态资源。
现在使用localhost:4000查看项目是否已经成功部署（localhost即项目宿主机的ip地址，如果部署在虚拟机则是虚拟机对应的ip地址）。

至此，Hexo项目所有前期工作皆以完成，接下只需要更换主题并加以美化

观察一下Next主题目录结构

  • _config.yml：通常是配置文件，用于存储整个项目或主题的各种配置参数，比如站点信息、主题相关设置等
  • LICENSE.md：包含项目的许可证信息，说明项目的使用许可条款等
  • package.json：记录项目的元数据，包括依赖项、脚本命令等信息，用于管理项目的依赖和构建等操作。
  • README.md：一般是项目的说明文档，介绍项目是什么、如何使用、安装步骤等相关信息，起到引导用户了解和使用项目的作用
  • _vendors.yml：与外部供应商、插件或者特定资源相关的配置文件
  • docs：通常用于存放文档相关的内容，比如项目的使用文档、说明文档等相关的源文件
  • languages：用于存放多语言相关的配置或文件，以支持项目的多语言特性
  • layout：存放页面布局相关的文件，用于定义网站页面的结构和样式布局
  • scripts：用来存放脚本文件，可能是自动化脚本、构建脚本、测试脚本等，用于辅助项目的开发、部署等流程
  • source：存放项目源文件的目录，比如主题的模板文件、内容文件等。

将项目代码提交到Github

事前准备

  • 注册Github账号(略)
  • 创建Github仓库
    1.登陆后在Github主页面右上角点击+号，然后选择“New repository”新建仓库
    2.Owner默认设置为自己，状态设置为Public
    3.选择一个license，然后点击创建
  • 在安装Git中设置的邮箱与用户要与此处一一对应
  • 在Deployment部分的仓库名也要与此处对应
  • 设置分支，默认为master或者main（可选）
    1.进入需要设置分支厂库的“code”页面，点击左上角的分支下拉框
    2.点击“View all branches”,在跳转后的页面中点击“New branch”新建分支（如Deployment这里我设置新的hexo/demo分支），你可以选择删除默认的分支，并将新建的分支设为新的默认分支，这样提交的代码就会保存到仓库的新分支里。假如你要使用Github page部署静态文件，并且有几个主题的项目需要提交到同一仓库中。管理好分支是很有必要的
  • 安装必要插件

使用SSH方式提交代码

  • 生成密钥，默认位置在~/.ssh。

  • 生成完毕后在~/.ssh文件夹下找到id_rsa.pub公共密钥

  • 进入Github设置(非仓库设置)，找到“SSH and GPG keys”

  • 点击“New SSH key”,将id_rsa.pub内容复制到其中，保存

  • 验证 SSH 连接

  • 使用hexo deploy提交代码到Github仓库

将Hexo项目部署到Netlify平台

总述：Netlify是一个流行的跨国代码部署平台，支持免费的个人版。使用Netlify可以快速高效部署网站，在国内可以直接访问并且访问速度也十分可观。

注册或登录Netlify

注：该过程需要授权Github或者其他Git仓库账号，请允许

创建需要部署的项目

  • 点击左侧“Sites”选项卡，然后点击右侧“Add new site”下拉框，选择“Import a exiting project”
  • 选择Github或者GitLab、Bitbucket、Azure DevOps，然后进行授权
  • 在“Let’s deploy your project with…”页面设置：
    1.Site name，注意该站点名字会影响最终访问的URL地址，务必认真填写
    2.Branch to deploy，选择需要部署仓库的具体分支，这里直接选择新分支或者默认分支即可
  • 点击Deploy以保存项目

Netlify的使用

创建完项目后Netlify便会立即开始部署，在“Sites”选项卡中会展示所有的项目。选择一个项目点击便会进入到对应的项目中，在“Sites/your-project-name”项目页面，你可看见项目的部署记录，当项目部署显示Published则表示部署成功。每次使用"hexo d"提交代码后，Netlify都会自动重新部署项目。
