k8s集群学习笔记

发表于 2025-05-20 更新于 2025-08-17 分类于 文章 ， 技术 ， Linux 运维

k8s发展与背景

kubernetes简称k8s，在希腊语中意为舵手，是一款开源的容器编排平台。在k8s诞生之前Google内部已经有一款非常成熟的管理工具Borg，依据Borg的设计理念Google公司推出了开源容器编排工具k8s。从项目部署的方式来看，其发展经历了三个阶段：

  • 传统部署时代：早期的应用程序直接部署在物理服务器上运行，由于物理服务器无法为应用程序定义确切的资源边界，导致了资源分配不均的问题。如一个服务器占用了大量硬件资源，导致其他所有的应用程序只能共用余下的资源。有事后又存在某个应用程序只占用了一小块资源导致了资源的浪费，进而导致成本上升
  • 虚拟化部署时代：为了解决传统部署方式的弊端，引入了虚拟化技术。虚拟化的核心思想是将一台物理服务器划分为多台虚拟机，每台虚拟机都具备完整的计算机功能。虚拟化技术可以更好的利用硬件资源，解决了传统部署方式的诸多弊端
  • 容器部署时代：容器类似于虚拟机，但相较于庞大的虚拟机容器显得更加小巧，可以很轻易的在不同平台间迁移

微服务、容器化技术的发展解决了资源利用率不高的问题。但随着容器的不断增多，如何管理这些容器成了一大难题，为了解决这些问题，k8s应运而生。其特点为:

轻量：所需的资源少
弹性伸缩/负载均衡/高可用：可以依据程序的负载情况自动增加或减少副本数量
可移植性高：可以在各种裸机或者云服务器运行

k8s架构总述


k8s采用主从架构设计，一个k8s集群通常由最少一个的Maste控制节点与最少两个的Node工作节点组成。其中控制节点为集群的控制平面，负责整个集群的决策与管理；工作节点负责为容器提供环境，是资源真正运行的地方

  1. Master
  • Scheduler：调度器，负责集群资源的调度，根据给定的规则将Pod调度到合适的Node上
  • API server：所有服务访问的统一入口，接受用户输入的命令，提供认证、授权等
  • Controller manager：控制管理器，负责实际运行集群以及集群状态的管理
  • etcd：存储集群数据的分布式键值存储数据库，1.11前的老版基于内存，新版基于数据库
  1. Node
  • kubelet：负责Pod生命周期的维护
  • kube-proxy：k8s网络代理，负责处理集群内部与外部的网络通信
  • 容器运行时环境：如Docker、Containerd、CRI-O，负责镜像管理和容器的实际运行
  1. 附加组件
  • Dashboard：图形化管理页面
  • Ingress Controller：提供外部访问入口
  • 日志系统：如Fluentd + Elasticsearch + Kibana（EFK）实现日志采集、存储与查询

k8s网络通信方式

kubernetes网络模型特点

  • 集群里的每个 Pod 都会有唯一的 IP 地址
  • Pod 里的所有容器共享这个 IP 地址
  • 集群里的所有 Pod 都属于同一个网段
  • Pod 直接可以基于 IP 地址直接访问另一个 Pod，不需要做网络地址转换（NAT）
  • Pod里面的容器共享network namespace(IP和MAC地址), 所以这些容器交互可以使用本地回环地址
同一Pod上容器间的通信(合租公寓) 图示
同一个Pod间的容器共享网络命名空间，可以直接通过localhost进行通信。即新创建的Docker容器不会创建自己的网卡或者配置自己的 IP，而是和一个指定的容器共享 IP、端口范围等。k8s中每个Pod都有一个pause容器，它拥有独立的网络命名空间，在Pod启动Docker容器时使用"–net=conatiner"就可以让当前Docker容器加入到Pod容器拥有的网络命名空间即pause容器。
同一Node内Pod间的通信(小区内径) 图示
每个Pod都有唯一的IP地址，可以直接通过访问IP进行通信。如图，Pod1和Pod2都是通过veth对连接到同一个Docker0网桥上的，并且和网桥的IP3在同一网段上，因此两者可以直接通过网桥进行通信。
不同Node间Pod的通信(跨城高速) 图示
同一Node下的Pod都在同一Docker0网桥上，因此可以直接通信。如果不同Node间需要通信则必须通过宿主机的物理网卡。为了实现Node间的通信，需要将Node和Pod所在的IP关联起来，并且保证没有任何冲突。如图，Pod1要访问Pod2，首先需要把数据发给Node1的eth0，然后找到Node2的eth0，接着才是传到Pod2的eth0.
Pod与Service间的通信 图示
在创建Service时k8s会为服务分配一个虚拟ip。通过此IP访问服务时，会由iptables负责转发，而iptables规则由kube-proxy组件维护。kube-proxy运行时会不断查询监听APIServer中Server和Endpoints的变化，以此来更新iptables的规则。
外部与Service间的通信 方法
集群外部无法直接通过Pod或Service ip访问集群内部，如果想要实现访问。则需要通过一些手段将内部ip暴露或者通过中间件将请求转接到集群内部 1. NodePort(临时收费站)：在k8s集群中的每个Node上打开一个主机的真实端口，如此便能通过此端口访问内部Service
2. LoadBalancer(云厂商专线):对Service的访问请求会通过LoadBalancer转发到后端Pod上
3. Ingress(智能路由):将集群内部服务暴露出来，以便直接从外部访问，Ingress则负责管理流量

k8s资源清单

必要属性

参数 类型 说明
version String k8s api的版本，目前基本上是v1，可用kubectl api-versions查询
kind String yaml文件定义的资源类型或角色，如pod、deployment
metadata Object 元数据对象
metadata.name String 元数据对象名字，自己定义，比如pod的名字
metadata.namespace String 元数据对象的命名空间，自己定义
spec Object 详细定义对象
spec.containers[].name String 定义容器的名称
spec.containers[].image String 定义时使用到的镜像名称

spec.containers[] 其他属性(在yaml中注意缩进格式，不要使用Tab间代替空格)

参数 类型 说明
spec.containers[].imagePullPolicy String 镜像拉取策略(默认Always)
Always:每次都尝试重新拉取
Never:仅经使用本地镜像
IfNotPresent:优先使用本地镜像，没有就拉取在线镜像
spec.containers[].command[] List 容器启动时的命令，不指定则使用容器打包时的启动命令
spec.containers[].args[] List 容器启动命令参数
spec.containers[].workingDir String 容器工作目录
spec.containers[].volumeMounts[] List 容器内部存储卷配置
spec.containers[].volumeMounts[].name String 可以被容器挂载的存储卷的名称
spec.containers[].volumeMounts[].mountPath String 可以被容器挂载的存储卷的路径
spec.containers[].volumeMounts[].readOnly String 存储卷路径的读取模式，true或false，默认为可读写模式
spec.containers[].ports[] list 容器需要用到的端口
spec.containers[].ports[].name String 设置端口名称
spec.containers[].ports[].containerPort String 指定容器需要监听的端口号
spec.containers[].ports[].hostPort String 指定容器所在主机需要监听的端口号，默认和containerPort一致(若设置此参数，则同一主机无法启动该容器的相同副本)
spec.containers[].ports[].protocol String 选择TCP或UDP作为端口协议，默认TCP
spec.containers[].env[] List 容器运行前所需的环境变量
spec.containers[].env[].name String 环境变量名称
spec.containers[].env[].value String 环境变量的值
spec.containers[].resources Object 指定资源限制和资源请求值
spec.containers[].resources.limits Obejct 设置容器运行时资源的上限
spec.containers[].resources.limits.cpu String 设置cpu资源的限制，单位为core数
spec.containers[].resources.limits.momery String 设置内存限制，单位为MiB、GiB
spec.containers[].resources.requests Obejct 设置容器启动和调度时的限制
spec.containers[].resources.requests.cpu Obejct 容器启动初始化可用cpu请求量，单位为core数
spec.containers[].resources.requests.memory Obejct 容器启动初始化可用内存请求量，单位为MiB、GiB

额外的属性

参数 类型 说明
spec.restartPolicy String 定义pod的重启策略(默认Always)
Always:pod一旦重启，无论何种原因导致中止kubelet都将重启它
OnFailure:只有pod以非0退出代码中止时，kubelet才会重启该pod
Never：pod中止后，kubelet将其报告给Master，但不会重启该pod
spec.nodeSelector Obejct node的Label过滤标签，以键值对形式指定
spec.imagePullSecrets Object 拉取镜像时使用的Secrets名称，以键值对形式指定
spec.hostNetwork Boolean 定义是否使用主机网络模式，默认为false，设置true则表示不使用docker网桥模式
